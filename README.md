# 4-Bit RISC CPU Datapath in Verilog HDL

A small 4-bit RISC-style CPU written in Verilog and simulated with AMD Vivado. It has a hardwired control unit, a two-stage fetch/execute pipeline, four general-purpose registers, and separate instruction and data memories (Harvard organisation). A self-checking testbench runs a demonstration program and reports PASS or FAIL for every step.

![CPU schematic generated by Vivado](docs/schematic.png)

## Highlights

- **Datapath:** 4-bit registers, ALU and data memory; 12-bit fixed-length instructions.
- **Memories:** 16 x 12-bit instruction ROM and 16 x 4-bit data RAM.
- **Registers:** R0 to R3 with two combinational read ports and one clocked write port.
- **Instruction set:** 13 instructions covering arithmetic, logic, data movement, memory access and jumps.
- **Flags:** Zero (Z) and Carry (C), stored in a flag register and used by `JZ` and `JC`.
- **Execution:** the clocked instruction register fetches the next instruction while the current one executes, so one instruction completes per clock.
- **Control:** combinational decoder with safe defaults; unused opcodes behave as NOP.
- **Verification:** self-checking testbench (17 checks) plus an ALU testbench with directed cases.

## Instruction format

```
 11      8 7    6 5    4 3          0
+---------+------+------+------------+
| opcode  |  Rd  |  Rs  | imm / addr |
+---------+------+------+------------+
  4 bits    2 bits 2 bits   4 bits
```

Rd is both the first source and the destination (`Rd = Rd op Rs`), which leaves room for a 4-bit immediate in the 12-bit word.

## Instruction set

| Opcode | Mnemonic | Operation | Flags |
|---|---|---|---|
| 0000 | `ADD Rd, Rs` | Rd = Rd + Rs | Z, C |
| 0001 | `SUB Rd, Rs` | Rd = Rd - Rs | Z, C |
| 0010 | `AND Rd, Rs` | Rd = Rd & Rs | Z (C cleared) |
| 0011 | `OR Rd, Rs` | Rd = Rd \| Rs | Z (C cleared) |
| 0100 | `XOR Rd, Rs` | Rd = Rd ^ Rs | Z (C cleared) |
| 0101 | `NOT Rd` | Rd = ~Rd | Z (C cleared) |
| 0110 | `LDI Rd, imm` | Rd = imm | none |
| 0111 | `MOV Rd, Rs` | Rd = Rs | none |
| 1000 | `LD Rd, [addr]` | Rd = MEM[addr] | none |
| 1001 | `ST Rd, [addr]` | MEM[addr] = Rd | none |
| 1010 | `JMP addr` | PC = addr | none |
| 1100 | `JC addr` | if C = 1 then PC = addr | none |
| 1111 | `JZ addr` | if Z = 1 then PC = addr | none |

Opcodes 1011, 1101 and 1110 are unused and act as NOP.

**Carry convention:** for `ADD`, C = 1 means the sum exceeded 15. For `SUB`, C = 1 means a borrow occurred (A < B). Logic instructions clear C.

## Architecture

| Instance | Module | Role |
|---|---|---|
| `PC_UNIT` | `program_counter` | Fetch address; loads PC + 1 or the jump address |
| `IM_UNIT` | `instruction_memory` | 16 x 12 ROM holding the program |
| `IR_UNIT` | `instruction_register` | Holds the fetched instruction |
| `CU_UNIT` | `control_unit` | Decodes the opcode into control signals |
| `FR_UNIT` | `flag_register` | Stores Z and C |
| `RF_UNIT` | `register_file` | Registers R0 to R3 |
| `ALU_UNIT` | `alu` | ADD, SUB, AND, OR, XOR, NOT; produces Z and C |
| `MUX_UNIT` | `mux` | Write-back select: ALU result, RAM data, immediate or Rs |
| `DM_UNIT` | `data_memory` | 16 x 4 RAM for `LD` and `ST` |

Write-back select (`reg_dst_src`): `00` ALU result, `01` RAM data, `10` immediate, `11` Rs.

## Branch delay slot

A jump is decided when the jump instruction is in the instruction register, so the next instruction has already been fetched. It still executes before the jump takes effect. Place a harmless or useful instruction right after every jump. In the demo program, `LDI R0, 15` after `JZ 8` runs even though the jump is taken.

## Demonstration program

| Addr | Hex | Instruction | Result |
|---|---|---|---|
| 0 | 645 | `LDI R1, 5` | R1 = 5 |
| 1 | 683 | `LDI R2, 3` | R2 = 3 |
| 2 | 060 | `ADD R1, R2` | R1 = 8 |
| 3 | 941 | `ST R1, [1]` | MEM[1] = 8 |
| 4 | 8C1 | `LD R3, [1]` | R3 = 8 |
| 5 | 170 | `SUB R1, R3` | R1 = 0, Z = 1 |
| 6 | F08 | `JZ 8` | jump taken |
| 7 | 60F | `LDI R0, 15` | delay slot, still executes |
| 8 | 580 | `NOT R2` | R2 = 12 |
| 9 | A09 | `JMP 9` | halt loop |

## Simulation

1. Create an RTL project in AMD Vivado (no board needed).
2. Add the files in `rtl/` as design sources and the files in `tb/` as simulation sources.
3. Right-click `testbench` and choose **Set as Top**, then run **Behavioral Simulation**.
4. In the Tcl console type `run all`.

A passing run ends with:

```
tb_cpu PASSED: 17 of 17 checks OK
```

To test the ALU alone, set `tb_alu` as top and run the same way.

## Known limitations

- The branch delay slot described above.
- After reset the instruction register is all zeros, which decodes as `ADD R0, R0` and sets Z once.
- Only 16 instruction words and 16 data words (4-bit PC and address field).
- No overflow or negative flag, and no subroutine support.

## Possible extensions

- Flush the instruction register on a taken jump to remove the delay slot.
- Reset the instruction register to an unused opcode (NOP).
- Add overflow and negative flags, `JNZ`, shifts and `CALL` / `RET`.
